# KVRouterKit 3.0.0

A clean break. There is no compatibility shim and no migration path from 2.x,
because effectively nobody depended on it yet.

## Highlights

- **Routes belong to the app.** `KVAppRoute` is gone. Declare your own value
  types conforming to `KVRoute`, and map them to views once in the composition
  root with `.kvRoutes { }`.
- **A port a ViewModel can depend on.** `KVRouterCore` holds the route model and
  the `KVRouting` command port with no SwiftUI, UIKit, Introspect or method
  swizzling behind it. `KVRouterTesting` ships a synchronous `KVRouterSpy`.
- **The router manages the navigation stack, nothing else.** Modals go back to
  SwiftUI's own `.sheet` and `.fullScreenCover`.
- **State restoration works across route types.** `KVPathCodec` persists a stack
  of mixed `KVRestorableRoute` types.
- **Eight latent defects fixed**, including a pop-bookkeeping flaw that could
  silently swallow `willPop` and a middleware chain that could wedge navigation
  for the rest of the process.

## Why Routes Moved Out

`KVAppRoute` was a closed enum of three cases, so "type-safe routing" in practice
meant `appFeature("product-detail")` — stringly typed — or `pushView { }`, which
makes a ViewModel build a View. Neither is usable from a presentation layer.

```swift
// The app's own routes: a plain value type, no SwiftUI in sight.
enum ShopRoute: KVRoute {
    case productDetail(id: Int)
    case cart
}

router.push(ShopRoute.productDetail(id: 42))
```

`pushView { }` keeps every capability it had. Its screens are now
`KVDynamicViewRoute` values — ordinary routes — so the router treats them like
any other and only view building tells them apart.

## Why Modals Left

Sheets are inherently local: presented from one view, closed with
`@Environment(\.dismiss)`, and `.sheet(isPresented:)` already models that
declaratively. Centralising them bought nothing and cost the most timing-sensitive
code in the package — a builder registry that leaked on swipe-to-dismiss, a
continuation that leaked if the router deallocated, and a 700ms guess in
`dismissSheetThenPresentFull`. All three left with the feature rather than being
patched.

The README carries the sheet-then-cover recipe: chain from `onDismiss`, which
fires when the dismissal actually completes.

## Fixes

- Pop bookkeeping used a single `isRouterControlledPop` flag. A flag cannot
  describe two pops in flight, and any path change that failed to shrink left it
  stuck — silently skipping `willPop` for the *next* system pop. Now per-entry.
- A system pop of several screens spawned one detached `Task` per screen, outside
  the FIFO queue the rest of the router is built around.
- The middleware chain had no watchdog, so one `await` that never returned wedged
  the operation queue permanently. It now races `middlewareTimeout`.
- `replaceTop(with:transition:)` recorded its transition and never played it.
  Rebuilt as a push followed by dropping the covered screen underneath.
- Swipe-to-dismiss on a zoom left the source view hidden: zoom metadata was
  pruned on the path change, which for an interactive dismissal happens before
  the animation ends.
- A zoom animated to and from square corners over a rounded source, because
  SwiftUI's `clipShape` never reaches `layer.cornerRadius`. Pass the radius via
  `kvTransitionSource(id:cornerRadius:)`.
- The coordinator was wired in `onAppear`, so swapping routers left it driving
  the previous one; `onDisappear` tore down the UIKit bridge, so a `TabView`
  switch dropped custom transitions until the tab came back.
- `@Environment(\.router)` defaulted to a real, unhosted router, so a missing
  `KVRouterHost` made navigation vanish with no crash and no log.

## Performance

Destination content observed the router with `@ObservedObject`, so any router
change — presenting a sheet included — invalidated every live destination and
re-ran its `AnyView` builder. The observation backend is also resolved once at
init rather than through an availability check and a cast on every property read.

## Added

`pageTurn(edge:)` joins the transition set: a 3D rotation pivoted on a spine
rather than the centre, so it reads as turning paper rather than flipping a card.
It is built on a new `anchor(_:)` transition primitive.

## Compatibility

- Minimum deployment target remains iOS 16.0.
- Swift 6.2 toolchain, Swift 6 language mode.
- The dual-observation layer stays: `@Observable` semantics on iOS 17+,
  `ObservableObject` on iOS 16. The fallback is asymmetric — `@Environment` does
  not observe an `ObservableObject` — so send commands rather than rendering from
  stack state.

## Verification

- 139 XCTest and 25 Swift Testing tests, run on an iOS 26.2 simulator.
- CI builds the example app for a generic iOS destination, which is the only
  consumer of the public API surface and catches breaks the package's own tests
  cannot see.
- The custom hero animator path was exercised on an iOS 16.0 simulator.
- Not covered: iOS 17, physical devices, and the visual quality of any
  transition — the harness cannot sample a frame mid-animation. See the Known
  Gaps section of the changelog.
